# SPEC · 项目规格（复发性心包炎工作台 v0.1 草案）

状态：草案 · 确认人：夜间自动签认（待晨审追认）· 0 患者访谈 · 0 临床审核（均如实标注）

## 问题、用户与最小闭环

复发性心包炎患者与照护者需要把「发作—缓解规律、炎症化验趋势、按次治疗、复诊材料」理成一份可核对的档案。输入：化验/超声/病历报告与手工记录；动作：核对入档、按次登记、趋势查看；输出：状态卡、区间带、可比趋势图、复诊清单。成功标准：两套合成档案下每条功能线有真实内容，私密三出口过滤，无任何判定性文案。失败恢复：录入三态按钮 + 更正新版本链。

## 方案与 ADR

- ADR-1 布局：business-first（主区业务 + 右侧 AI 面板 35% 可拖 25–45%），与小粉宝/小橙宝一致；拒绝弹窗式 AI。
- ADR-2 第一实体选型：候选 A「随访节律型」（照抄 R2 仓）；候选 B「发作事件型」；候选 C「治疗线型」（肿瘤语义，禁用）。选 B：病程核心是发作—缓解交替，其余实体（化验/治疗/就诊）都挂在发作与缓解节点上。
- ADR-3 试验线裁剪：见 DEV-PLAN §四；设置页临床数据库 tab 如实标注裁剪与快照状态。
- 宿主能力：本机优先，apiBase 契约按 02 号；MinerU 未接入如实标注。

## 功能范围

见 INTERACTION-DESIGN.md 导航全量与 SCENARIOS S1–S7；稳定功能 ID 在 M2 建 FEATURE-INVENTORY。核心页：home（状态卡）、events（区间带时间线）、labs（一图秀）、treatment（按次登记）、visits、reports、mind、records、settings（三 tab）、primer（疾病概要）。

## 数据与 API

实体：档案(profile)、发作事件(flap,含开始/缓解日期与状态)、化验(lab,指标/值/单位/方法/机构)、治疗记录(treatment,按次与日常)、报告(report,原件引用)、医院(hospital)、问题清单(visit_question)、笔记(mind_note)。判读列 0（无 diagnosis/risk_level/活动度列）；派生值（缓解第 N 天等）读时算不落库。详见 M3 schema。

## 设置与配置页面

三 tab（工作区/文档解析/临床数据库）：资料目录口径「拒绝主目录/桌面/下载根/tmp」；MinerU 未接入态「勾选与保存不联网」+ Flash 免费 10MB/20 页上限文案；临床数据库 tab 显示快照条数/日期/通道终态（与实际使用一致，含裁剪说明）。
